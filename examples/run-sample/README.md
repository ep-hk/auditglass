# A complete run directory

This is the output of `auditglass demo`, committed so that you can evaluate what the
tool records **without installing anything**. If you are assessing this project for a
regulated environment, this directory is the fastest way to decide whether the audit
trail meets your requirements.

Read in this order:

| File | What it answers |
|---|---|
| [`report.md`](report.md) | What an on-call engineer actually receives. Note that every finding cites the evidence ids it rests on. |
| [`manifest.json`](manifest.json) | Which configuration, policy, template set and reasoner produced this, with hashes. Answers "what exactly was running?" |
| [`queries.jsonl`](queries.jsonl) | Every query dispatched, as `template_id` + typed parameters + the rendered statement. This is the complete set of things the run asked a backend. |
| [`evidence/`](evidence/) | The records themselves, after pseudonymisation, one file per evidence id. |
| [`redactions.jsonl`](redactions.jsonl) | Which rule fired at which offset in which field — and never the original value. |
| [`report.json`](report.json) | The same findings in machine-readable form. |

## Things worth noticing

**Pseudonyms preserve correlation.** In `evidence/E1.json`, `client_ip` values are
tokens like `IP_2757cb6f`. The same address always yields the same token, so "eight
errors from one client" is still visible. The original value never left the
organisation.

**Injected content is marked, not hidden.** `E1` carries
`"injection_suspected": true`. One of the synthetic log lines contains text addressed
to an AI system, including a Markdown image pointing at an attacker-controlled URL.
The report surfaces it in its own section and renders it inert — the `![` sequence is
escaped so no client fetches that URL — while `evidence/E1.json` keeps the record
verbatim for forensics.

**Queries are template selections, not strings.** Each line of `queries.jsonl` names
a template and its parameters. A reviewer does not need to read LogQL to audit what
was asked for.

**A real run of this would have `denials.jsonl` and `gaps.jsonl`** if anything had
been refused or had failed to return. They are absent here because nothing was. Run
`auditglass demo --simulate-outage` to see the gap path.

## What is missing on purpose

`reverse-map.json` — the file mapping tokens back to original values — is **not**
committed. In a real run it is written to the run directory with mode `0600` and never
leaves it; `redaction.write_reverse_map: false` stops it being written at all.

## Provenance

Every record here is synthetic, generated by
[`demo/generate_fixture.py`](../../demo/generate_fixture.py). Addresses are RFC 5737
documentation ranges, domains are RFC 2606 reserved names, and the card numbers are
Luhn-valid but belong to no issuer's live range and to no person. No production
system is described by any of it.
